# `upstream_mapping_must.csv` — 생성 원리와 컬럼 의미

본 문서는 `metadata_outputs/upstream_mapping_must.csv`가 **어떻게 만들어졌는지**, 각 필드가 **무엇을 의미하는지**, 그리고 **TFT 등 모델 입력**에서 어떻게 쓰면 되는지 정리한다.

---

## 1. 파일의 역할

수계 내 관측소 간 **상류 연결(업스트림 맵)**을 고정한 메타데이터다. `stream_code` 단위로 “누가 누구의 상류인지”를 나열하고, DAG 원칙 위반이나 비현실적 연결은 검토 과정에서 제거·수정한다.

---

## 2. 생성 원리

1. **`stream_code`로 그룹**을 나눈다.
2. 그룹 안에서 **`station_id` 오름차순**으로 이웃 관측소를 상류 방향으로 연결한다.  
   - 여기서 오름차순은 **“수계 상류 → 하류” 방향을 가정한 규칙**이다(지리적 진실이 아니라 정렬 기반의 초기 연결).
3. 연결 결과에 대해 **DAG 원칙 위반**과 비현실적 패턴을 직접 검토한다.  
   - 예: 순환, 역류(하류→상류), 독립 수계 혼입, 본지류 역전, 터미널 노드(갑문·하구·바다 등)와의 부적절한 연결 등.

검토 후 남는 **`upstream_1`, `upstream_2`**는 모델이 사용할 **상류 관측소 ID**다.

| `upstream_*` 값 | 의미 |
|-----------------|------|
| **유효 ID** | 검토를 통과한 상류 후보 |
| **NaN(비어 있음)** | 실제 최상류이거나, 검토 중 **잘못된 연결로 판단되어 제거**된 경우 |

**NaN인 상류 슬롯**에 대해서는 해당 **lag 피처를 만들지 않는다**(아래 TFT 절 참고).

---

## 3. `upstream_*_lag0` 플래그

`upstream_1_lag0`, `upstream_2_lag0`는 그 `upstream_*` 값이 **“진짜 상류 관계인지”**를 나타낸다.

| 값 | 의미 | lag 피처 |
|----|------|----------|
| **`False`** | 정상 상류 관계 | lag 피처를 **그대로 생성·사용** |
| **`True`** | 실제 상류가 없어 **fallback으로 임시 채운 값** | 피처 **컬럼은 유지**하되, 값은 **0으로 마스킹** |
| **NaN** | 해당 슬롯에 `upstream` 자체가 없음 | 해당 lag 피처 **컬럼 자체를 생성하지 않음** |

---

## 4. TFT(및 유사 파이프라인) 적용 요약

- **`lag0 == False`** → 정상 사용.
- **`lag0 == True`** → 피처는 두되 **값은 0 처리**(마스킹).
- **`upstream`이 NaN** → **해당 lag 피처 컬럼을 만들지 않음**.

---

## 5. `fix_1`, `fix_2`

검토하면서 **연결을 제거·복원·수정한 이유**를 남긴 기록용 필드다. **모델 입력에는 사용하지 않아도 된다**(감사·재현·수동 판단 근거 추적용).

---

## 6. `fix_*` 코드 해설 (문자열 패턴)

아래는 파일에 등장할 수 있는 태그를 **의미 단위로** 묶어 설명한 것이다. 실제 문자열은 접두·접미가 붙을 수 있다.

| 패턴 / 예시 | 해석 |
|-------------|------|
| **`R1_lag0`** | fallback(lag0=True) 쪽 연결을 **제거**한 경우 |
| **`R3_terminal`**, **`terminal_*`** | 갑문·하구·바다 등 **터미널 노드**와의 연결을 제거 |
| **`역류_*`**, **`본지류역전_*`** | 하류→상류 같은 **역방향**·본지류 역전으로 보이는 연결 제거 |
| **`*_혼입`** | **다른 수계**로 잘못 이어진 연결 제거 |
| **`WHITELIST_*`** | 자동 규칙상 문제로 보였으나, **실제로 맞는 댐 직하류 등**으로 판단되어 **수동 복원** |
